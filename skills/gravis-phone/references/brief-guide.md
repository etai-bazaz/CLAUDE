# מדריך ה-brief

ה-brief הוא כל מה שהמודל בשיחה יודע. מה שלא כתוב בו לא קיים מבחינתו. לכן כותבים אותו מלא, קצר וחד.

## מצב third_party: כל השדות

| שדה | חובה | מה כותבים |
|---|---|---|
| `mode` | ✔ | `"third_party"` |
| `to` | ✔ | המספר כפי שאושר, למשל `"03-555-1234"`. הסקריפט ממיר ל-E.164. |
| `callee_name` | ✔ | שם העסק או האדם, למשל `"מוסך אורן"`. |
| `callee_kind` |  | `business` / `office` / `clinic` / `person` |
| `purpose` | ✔ | **צירוף שם עצם** שבא אחרי "בקשר ל...", למשל `"קביעת טיפול לרכב"`, `"בירור הצעת מחיר להובלה"`. לא משפט שלם. |
| `goal` | ✔ | מה רוצים להשיג, במשפט אחד. |
| `success` | ✔ | מתי השיחה הצליחה. לפי זה המודל יודע מתי לסיים. |
| `questions` |  | רשימת שאלות. שאלה אחת בכל שורה, לפי סדר חשיבות. |
| `context` |  | הפרטים שמותר לשתף, ורק אותם (דגם רכב, סוג תקלה, מספר הזמנה). ת"ז, כתובת או טלפון נכנסים רק באישור מפורש של איתי לשיחה הזו, ועם המטרה: `"ת\"ז לזיהוי בלבד, אם המרפאה מבקשת: ..."`. אשראי, סיסמאות וקודים — אף פעם. |
| `mandate` |  | למה מותר להסכים, עם גבולות מספריים. ריק = רק בירור. |
| `never_share` |  | איסורים נוספים, ספציפיים למשימה. האיסורים הכלליים כבר בתבנית. |
| `transfer_to_owner` |  | `true` רק כשאיתי רוצה שיעבירו אליו את השיחה, למשל "תחכי על הקו ותעבירי אליי כשנציג עונה". |
| `on_voicemail` |  | `"hang_up"` (ברירת מחדל) או `"leave_message"` |
| `voicemail_message` |  | הודעה קצרה בלשון ניטרלית, עם מספר חזרה רק אם איתי אישר. |
| `max_minutes` |  | ברירת מחדל 6. בהמתנה במוקד: עד 15, וזו גם התקרה הקשיחה. |
| `notes_for_agent` |  | הגייה של שמות, הקשר תרבותי, ניואנסים. |
| `opening_line` |  | רק כדי להחליף את משפט הפתיחה הקבוע. הוא חייב להכיל גילוי AI ואת שמו של איתי. |

## מצב decision: כל השדות

| שדה | חובה | מה כותבים |
|---|---|---|
| `mode` | ✔ | `"decision"` |
| `topic` | ✔ | הנושא בכמה מילים. נכנס למשפט הפתיחה: "...החלטה קצרה לגבי {topic}". |
| `question` | ✔ | שאלה סגורה אחת. |
| `options` |  | עד 3 אפשרויות. כל אחת קצרה, עם המספר הכי חשוב בה. |
| `recommendation` |  | ההמלצה שלך + נימוק במשפט. |
| `context` |  | 1–3 עובדות שאיתי צריך כדי להחליט. |
| `default_if_no_answer` | ✔ | מה עושים אם אין החלטה. חייב להיות בטוח: בדרך כלל "לא עושים כלום, ממשיכים בשאר". |
| `max_minutes` |  | ברירת מחדל 3. |

## כללי עברית מדוברת (חשוב)
התבנית כבר מורה למודל איך לדבר. ה-brief צריך לעזור לו:
- **ספרות ב-brief זה בסדר** (`"עד 900 ₪"`, `"08:00–12:00"`). המודל מתורגל לומר אותן במילים. אל תכתבי "תשע מאות" ב-brief, זה רק מבלבל.
- **שמות בלי ניקוד** עלולים להישמע לא נכון. שם שיש בו ספק הולך ל-`notes_for_agent` עם הגייה, למשל `"בזז נהגה ba-ZAZ"`.
- **פנייה ניטרלית:** המודל לא יודע מי עונה. אל תכתבי ב-brief "תשאלי אותו" או "תבקשי ממנה". כתבי "לשאול", "לבקש".
- **שאלה אחת לכל פריט.** "מה המחיר וכמה זמן זה לוקח?" מתפרק לשתי שאלות.
- **בלי ז'רגון פנימי** ("לופ", "גרוויס משימה 3"). הצד השני שומע את כל מה שהמודל אומר.

## דוגמה 1: קביעת תור עם מנדט מוגבל
```json
{
  "mode": "third_party",
  "to": "03-555-1234",
  "callee_name": "מוסך אורן",
  "callee_kind": "business",
  "purpose": "קביעת טיפול לרכב",
  "goal": "לקבוע תור לטיפול שלושים אלף למאזדה 3 עד סוף אוקטובר",
  "success": "נקבע תור בתוך המנדט, או שיש לנו את שלושת המועדים הקרובים והמחיר",
  "questions": ["מה המחיר של טיפול שלושים אלף למאזדה 3?", "כמה זמן הרכב נשאר במוסך?", "יש רכב חלופי?"],
  "context": ["מאזדה 3, שנת 2021", "29,800 ק\"מ"],
  "mandate": ["מותר לקבוע תור בימים ראשון או שני בין 08:00 ל-12:00, עד 31.10", "מותר להסכים למחיר עד 900 ₪ כולל מע\"מ"],
  "never_share": ["מספר רכב"],
  "on_voicemail": "hang_up",
  "max_minutes": 6
}
```

## דוגמה 2: בירור בלבד, בלי מנדט
```json
{
  "mode": "third_party",
  "to": "08-6123456",
  "callee_name": "מרפאת שיניים ד\"ר לוי",
  "callee_kind": "clinic",
  "purpose": "בירור תורים פנויים להלבנת שיניים",
  "goal": "לברר מחיר ותורים פנויים להלבנת שיניים בנובמבר",
  "success": "יש מחיר ולפחות שני מועדים פנויים",
  "questions": ["מה המחיר להלבנה?", "אילו תורים פנויים יש בנובמבר?", "צריך בדיקה מקדימה?"],
  "context": [],
  "on_voicemail": "hang_up"
}
```
`mandate` לא הוגדר, ולכן גרוויס רק מבררת. אם המזכירה מציעה לשריין תור: "אבדוק עם איתי ואחזור אליכם".

## דוגמה 3: המתנה במוקד והעברה לאיתי
```json
{
  "mode": "third_party",
  "to": "1-700-700-123",
  "callee_name": "שירות הלקוחות של חברת הסלולר",
  "callee_kind": "office",
  "purpose": "חיוב כפול בחשבונית האחרונה",
  "goal": "לעבור את התפריט, לחכות לנציג אנושי, ולהעביר אליו את איתי",
  "success": "נציג אנושי על הקו והשיחה הועברה לאיתי",
  "questions": [],
  "context": ["הנושא: חיוב כפול בחשבונית אוקטובר"],
  "notes_for_agent": ["בתפריט בחרי את האפשרות של בירורי חיוב או שירות לקוחות", "כשנציג עונה: הציגי את עצמך במשפט, אמרי שאיתי בעל הקו ממתין להעברה, והעבירי"],
  "transfer_to_owner": true,
  "max_minutes": 15
}
```
שימו לב: מספר 1-700 עלול לא להיות נגיש מפלטפורמה בחו"ל. אם החיוג נכשל, צריך לחפש מספר רגיל של המוקד.

## דוגמה 4: החלטה מאיתי
```json
{
  "mode": "decision",
  "topic": "ביטוח הרכב",
  "question": "איזו הצעה לקחת?",
  "options": ["הראל, 3,200 ₪ לשנה, השתתפות עצמית 1,500", "מגדל, 2,900 ₪ לשנה, השתתפות עצמית 2,500"],
  "recommendation": "הראל. ההפרש בפרמיה קטן מההפרש בהשתתפות העצמית",
  "context": ["הפוליסה הנוכחית נגמרת ב-1.11"],
  "default_if_no_answer": "לא לבחור כלום, לשלוח לך השוואה מסודרת בצ'אט, ולהמשיך בשאר המשימה"
}
```

## בדיקה עצמית לפני חיוג
- [ ] איתי אישר את **הכרטיס הזה**, לא כרטיס קודם.
- [ ] המספר אומת, והמקור שלו ידוע.
- [ ] `purpose` הוא צירוף שמני שמתאים אחרי "בקשר ל...".
- [ ] המנדט מספרי וחד, או ריק בכוונה.
- [ ] אין ב-`context` פרטים מזהים מיותרים.
- [ ] הרצת `--dry-run` וקראת את ה-prompt שנוצר.
